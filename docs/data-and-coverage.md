# Data sources and coverage

## Public sources

The catalog is collected from OSU's public [class search](https://classes.osu.edu/) and [class-search JSON endpoint](https://content.osu.edu/v2/classes/search). Available term codes can be checked through [OSU's searchable terms endpoint](https://content.osu.edu/v2/classes/searchableTermsV2). The public feed is an upstream dependency rather than an API whose compatibility we control.

The public app contains only the upcoming semester, Spring 2027 (`1272`), across Columbus, Lima, Mansfield, Marion, Newark, and Wooster. The collector also keeps Autumn 2026 (`1268`) in its private working directory as instructor-search history; those past offerings are excluded from public catalog files and the semester selector. Subject discovery selects the requested term in the official public search form before reading its options; the entry form initially defaults to a different term. Campus inventory and independent section totals come from the official API. The published index, `coverage`, and section timestamps are the authoritative record of what a particular build includes.

The October 20, 2026 collection verified **7,787 Spring course offerings and 26,594 unique sections**, matching OSU's independent campus totals: Columbus 25,048; Lima 239; Mansfield 241; Marion 274; Newark 556; Wooster 236. The JSON feed directly publishes instructor names for 20,864 of those sections. Qualified matches remain separate from this published-name total. The [university collection receipt](../data/discovery/university-collection.json) records source counts, checks and unfinished discovery work.

The broad API response caps results at 10,000 and includes only ten subject facets. It cannot establish full university coverage on its own. Collection partitions by subject and campus, uses supported catalog-number sorting, checks unique section counts, and retries inconsistent subject pagination. The orchestration script compares collected campus totals with separate official campus counts before publishing.

`data/catalog-contract.example.json` describes the normalized shape. It is a contract example, not real data. The production entry point is `frontend/public/data/catalog-index.json`; its immutable files under `catalogs/` each contain a validated catalog with disjoint semester/campus/subject scopes. Never substitute invented instructors, seat counts, reviews, or grades to fill gaps.

## What the data means

| Field                       | Interpretation                                                                                                                                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Term and campus             | Source scope; the same course can differ across terms/campuses.                                                                                                                                                                              |
| Course ID                   | Normalized term/campus/subject/catalog-number identifier.                                                                                                                                                                                    |
| Section ID / class number   | Identifies an offering within its term; sections can have multiple meetings or instructors.                                                                                                                                                  |
| Instructor list             | Full names published by the JSON feed. An empty list can still have separate surname-search evidence.                                                                                                                                        |
| Instructor discovery        | `SURNAME_MATCH` records one matched surname; `AMBIGUOUS` records multiple surname candidates. Optional `fullNameMatches` links reviewed full-name candidates with `LIKELY` confidence. Neither is an official primary-instructor assignment. |
| Meetings                    | Published days, times, dates, and location. Missing times can represent asynchronous or arranged meetings.                                                                                                                                   |
| Enrollment status           | Status observed at collection time. An OPEN label is not a current seat guarantee.                                                                                                                                                           |
| Section details             | Session and dates, associated class, automatic enrollment sections, instructor/department consent, location, and section attributes when supplied. |
| Capacity / available seats  | The explicit “Check current seats” action fetches official availability with its own timestamp. Base snapshots do not substitute classroom capacity for enrollment capacity. |
| Last updated / generated at | Collection timestamps, not guarantees that OSU has finalized the assignment.                                                                                                                                                                 |
| Coverage                    | Imported scope, verified pagination counts, and warnings. Completeness describes the base section inventory, not whether every instructor has been identified. |

The application distinguishes published full names, surname-search evidence, ambiguous candidates, and unknown assignments. Grading basis and repeat/enrollment policy fields are not yet normalized; confirm those policies in the linked official course source. It does not query student enrollment accounts, scrape RateMyProfessors, infer instructor quality, or publish grade distributions.

## Instructor discovery coverage

The public [OSU PeopleSoft class search](https://courses.erppub.osu.edu/psc/ps_1/EMPLOYEE/CAMP/c/COMMUNITY_ACCESS.CLASS_SEARCH.GBL?PAGE=SSR_CLSRCH_ENTRY) can return current-term class numbers for an exact instructor-surname query even when the JSON feed omits instructor names. Discovery verifies the returned semester/campus/subject/surname criteria and an empty negative-control query before joining class numbers to the selected catalog scope. No login or student credentials are used.

The production refresh derives candidates separately for every subject from published current and historical instructor names. Reviewed CSE directory names supplement CSE only. Display names without an explicit family-name field produce surname suffix alternatives, including compound surnames; those strings are search inputs and do not establish an identity. Never-searched queries run before checks repeated after an inventory change or expiry, so busy subjects cannot indefinitely block the remaining queue. Names from another department never become a same-surname identity match merely because they appear elsewhere in the university catalog. An unresolved row means that current public records and completed searches have not identified the instructor; it does not establish that OSU has no assignment.

The university runner checks up to 40 surnames in each atomic batch. It retains successful-query timestamps and scope fingerprints in its working state, resumes unfinished batches before repeating expired checks, and requeues completed searches when a subject's section inventory changes or the refresh interval expires. The default daily discovery budget is 20 minutes; the last batch may finish after that budget. A zero-minute setting processes the full pending queue. A source failure retains that batch's previous evidence and leaves its names pending. Receipts report failures and unfinished searches rather than claiming exhaustive discovery.

The earlier October 20 CSE collection checked 180 surnames and added full-name candidates to 360 previously unpublished CSE sections. Its receipt, [`cse-expanded-collection.json`](../data/discovery/cse-expanded-collection.json), records that historical collection and its limits; the current catalog and university collection receipt provide current counts. All seven CSE 3521 sections had likely full-name matches in that initial expanded collection.

CSE 3421 classes **6248** and **36012** both match **Lee**. The UI links that evidence to **Rubao Lee — Likely match** using his [official CSE profile](https://cse.osu.edu/people/lee.11875), published CSE 3421/5421 teaching history retained as collection input, and the reviewed current-year supporting source. This provides a usable full name and rating-page link while keeping the section assignment inferred. The public surname result does not establish whether a match is the primary instructor, another associated instructor, or a coordinator. Multiple surname/full-name candidates remain visible and are excluded from “Identified instructors only” when no single candidate is supported.

The reviewed registry is [`data/discovery/cse-instructor-identities.json`](../data/discovery/cse-instructor-identities.json), with stable published instructor IDs, full names, official records, source URLs, `LIKELY` confidence, and review times. It supplies curated overrides rather than restricting discovery to those people. Other same-subject full names can be linked from official current/historical catalog records, preserving multiple supported candidates for a surname. Source buttons say “Official OSU records” because a link can be an individual profile or a catalog record. Names appear in search, profiles, comparison, saved plans, and calendar exports with their qualification. Candidates stay in `instructorDiscovery.fullNameMatches`; they never enter the official `instructors` list. Yoonkyung Lee also has a CSE courtesy appointment, so no globally unique “Lee” identity is claimed; Rubao's reviewed candidate uses course-specific context. See [`full-name-identity-review.json`](../data/discovery/full-name-identity-review.json).

Catalog-backed identity resolution uses the strongest available teaching-history tier: the same course first, then course numbers differing by 2,000, then same-subject surname candidates. Every candidate within the selected tier remains visible and `LIKELY`; course-number proximity is context, not proof of an assignment or an official course pairing. Record links point to the historical OSU class-search response that actually published the full name.

Historical course context also comes from checked-in [Spring 2026 Registrar associations](../data/discovery/cse-expanded-3521/spring2026-cse-course-associations.json), extracted and reviewed against the official schedule. The roster collector loads this evidence without downloading or parsing a PDF at runtime. It uses fully printed names and unambiguous identity matches for course affinities; initials do not become invented given names. A historical association strengthens candidate selection but does not establish the current assignment.

RateMyProfessors links use individually verified profile URLs when reviewed; otherwise they open a name search scoped to Ohio State's school page. A search link is not a verified rating-profile match. The application imports no ratings or review text and does not use them to establish section assignments.

The expanded seed file is [`data/discovery/cse-surnames.txt`](../data/discovery/cse-surnames.txt), combining official directory names and known teaching records; the importer also derives candidates from its current and prior catalog input. The earlier experiment's per-query evidence remains in [`data/discovery/cse-surname-pilot/evidence.json`](../data/discovery/cse-surname-pilot/evidence.json). Older published names supply candidates only; current-term query matches supply section evidence. Available history and public search behavior limit coverage, so a failed/absent match cannot prove that a professor is unassigned. The catalog's `coverage.complete` describes base course-feed pagination, not exhaustive instructor-search coverage.

Each section's optional, nullable `instructorDiscovery` contains the status, candidate surnames, source URL, check time, and `PEOPLESOFT_EXACT_LAST_NAME` method. `SURNAME_MATCH` requires exactly one nonempty distinct surname; `AMBIGUOUS` requires at least two. Optional `fullNameMatches` contains reviewed candidate objects with identity IDs, names, surname, profile/rating URLs, official source URLs, confidence, and an independent `checkedAt`. `instructors` remains the separate published-full-name list. The contract example uses placeholders for documentation, not assignments. Evidence and identity review times are independent of the base catalog's collection time. Revalidating one surname removes its stale match when it no longer appears; untested cached names retain their original evidence time.

## Collection behavior

The Java importer requests configured subjects, or `ALL`, for one campus and term. It follows pagination, normalizes all published instructors and meetings, and validates the candidate before an atomic working-file replacement. When discovery is enabled, it completes the requested search batch before writing it. A shrinkage check protects against unexpectedly large section-count drops. The Python university runner coordinates the campus imports and resumable searches, and the static publisher validates all shards before atomically replacing the public index.

Seat availability uses the public `https://content.osu.edu/v2/classes/availability` endpoint with the original term, session, offering, course ID, and section identifiers. OSU allows browser access to this endpoint. Requests happen only when the user chooses “Check current seats”; a failure leaves the collected snapshot visible. Capacity and available seats can reflect combined-section rules, so these values do not validate a student's enrollment eligibility.

Refreshing a configured term/campus/subject scope preserves unrelated subjects, campuses, and terms already present in the output. Historical records retain their own section timestamps in the private working cache. Publication filters courses, coverage and metadata to the requested upcoming term, including when resuming searches on a previously combined working file.

Scope changes require review. Counts can legitimately fall when OSU cancels sections or when maintainers narrow an import. Do not mark a dataset complete merely because the first page returned successfully. Keep comparisons against a previous successful snapshot and sample official pages whenever changing source parsing.

## Planning limits and privacy

The planner helps compare meeting times. A section selection does not validate lecture/lab pairing, prerequisites, waitlist rules, reserved seats, degree applicability, campus travel, or enrollment eligibility. Asynchronous or missing meeting times cannot establish that two choices are conflict-free. Confirm your final plan through OSU's official enrollment system.

Saved selections stay in browser local storage and can be removed through the UI or browser settings. They are not transmitted to an application account or shared automatically across devices. Hosting providers may maintain normal access logs. Do not place student names, IDs, credentials, or enrollment exports in this repository or its public dataset.
